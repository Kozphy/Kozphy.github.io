Product schema · WP-FIN-001

Risk → control → test →
exception → conclusion.

Sample evidence-pack shape for design-partner pilots. Educational / synthetic — not a client file, not an assurance service or audit opinion.

Type: product demo / educational sample.

Process: ingest → validate → quarantine exceptions → clean → report for a financial CSV export.

Reference: financial-data-automation · recon demo.

1 · Objective

What we are trying to prevent.

Prevent silent data loss, unreviewed corrections, and untraceable totals when a financial CSV is transformed into a report.

2 · Key risks

Where the process can fail.

Risk register · sample
ID Risk Why it matters
R1 Invalid or incomplete source rows enter reporting totals Downstream analysis and decisions inherit bad inputs
R2 Exception rows are dropped without a review trail Material omissions become invisible to reviewers
R3 Assumptions are mixed into reported facts Reviewers cannot tell what was measured vs modeled
R4 Results cannot be reproduced after the fact No reliable reperformance path for QA or audit follow-up

3 · Control matrix

Designed responses.

Control matrix · sample
Control Risk Type Owner / evidence
C1 Schema + completeness validation before cleaning R1 Preventive · automated Validation step output; failing rows never enter clean totals
C2 Quarantine with reject reason (no silent drop) R2 Detective · automated + review Exception log / quarantine file available for human decision
C3 Separate reported inputs from model assumptions R3 Preventive · design Case memo + UI labels; assumptions adjustable only in scenario controls
C4 Locked expected outputs + reproduction commands R4 Detective · automated pytest / case assertions; pinned revision commands on case page
C5 Append-only process log R2, R4 Detective · automated JSONL / audit-style event trail for reperformance

4 · Tests performed

How I would reperform this.

T1 / WALKTHROUGH

Trace one row end-to-end.

Pick a valid row and an invalid row. Confirm only valid rows reach clean totals and invalid rows appear in quarantine with a reason.

T2 / REPERFORMANCE

Rerun the locked case.

Execute the pinned pytest commands. Confirm FCF proxy 98,767 and base illustrative value $143.49/share still match.

T3 / EXCEPTION REVIEW

Inspect planted / rejected cases.

For AI evaluation evidence, confirm graders catch planted finance errors and that FAIL triggers when critical-error thresholds are exceeded.

5 · Exceptions

What remains open.

  • Sample uses educational / synthetic datasets, not a live client extract.
  • FinOps control design evidence is docs-only in public form.
  • No claim of SOX reliance, ITGC operating effectiveness, or audit opinion.

6 · Conclusion

Fit for pilot scoping.

For the stated educational process, designed controls address R1–R4 with observable evidence paths. A buyer can reperform the recon demo and inspect the export schema. This does not constitute assurance over any production system.
